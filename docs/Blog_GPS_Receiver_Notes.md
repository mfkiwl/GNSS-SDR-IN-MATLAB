## 2. 捕获部分（第 6 篇）

### 2.1 算法选型结论

- **并行码相位 FFT-IFFT**（搬频到零频 → 数据 FFT=A → 本地伪码 FFT=B → C=IFFT(A·conj(B))）：
  一次性搜索全部码相位，速度快、结构简单——与本项目 `acquisition.m` 的 FFT 圆周相关
  思路一致，设计方向得到旁证。
- 缺点：**对 1 ms 积分内的电文翻转抗性差**（180° 翻转会让相关趋近 0）。与本项目
  踩坑 14「5 ms 相干捕获多周期歧义」同源，都是积分时长与电文/周期结构之间的权衡。
- 备选：短时相关+FFT（相关器搜码 + FFT 搜频），资源灵活但时序复杂。

### 2.2 参数设计参照

- 多普勒范围：卫星运动最大 ±5 kHz，叠加接收机运动一般 **±10 kHz 内**（高动态另论）
  ——本项目的 ±10 kHz 默认范围合理。
- 频率精度：希望捕获误差 ≤200 Hz → FFT 频点间隔 ≤400 Hz → 分析时长 ≥2.5 ms
  （64 点 FFT，20 段 50 µs 数据补零到 3.2 ms，实测误差 156 Hz）。本项目 500 Hz 步进
  误差 ±250 Hz，若真实卫星后想收紧，可参照此思路做两段式。
- 码相位：**半码片精度即可**（GPS 2046 个；实现按 2083 个）。本项目码相位为采样点
  粒度（2.5 MSPS 下约 0.4 chip/采样点），精度更高。
- 非相干累加：1 ms 相干 × 10 次非相干（30 ms/星完成捕获，32 星 <1 s）。

### 2.3 排障与经验

- **搬频方向反了是常见错误**：作者用 ILA 抓数据 → 与 Verilog 等价的 MATLAB 模型分析，
  发现混频方向反了导致无相关峰；修正后立即出峰。本项目可在真实卫星前自检混频方向。
- 捕获判决用 signal/noise 比值（串口打印 signal 与 noise 分开），并与手机
  "GPS Test" 观测的可见星/信号强度**完全吻合**——说明捕获结果可直接与手机 App 交叉验证。
- **大型算法工程必须配 MATLAB/C 参考模型**，否则排障成本极高；本项目本身就是 MATLAB
  工程，天然具备该优势。

## 3. 跟踪部分（第 7、9 篇）

### 3.1 环路结构与参数（可直接对照 `tracking.m`）

| 环路 | 带宽 | 鉴别器 | 阶数 |
|---|---|---|---|
| FLL | 100 Hz | 归一化二象限反正切（频率） | 二阶 |
| PLL | 20 Hz | 二象限反正切（Costas，抗电文翻转） | 二阶 |
| DLL | 2 Hz | 归一化超前减滞后包络 | 二阶 |

- **跟踪流程：先 FLL 收敛频率 → 停 FLL、跑 PLL 收敛相位**（相位收敛则频率自然收敛）。
  本项目当前为 PLL+DLL、无 FLL（HANDOFF §9.2 也把「PLL 加 FLL 辅助」列为待办）——
  这正是该博客可落地的第一项。
- 相干时间：初期 1 ms，**位同步后切 20 ms 相干累加**——与本项目一致。
- 码环/载波环短时相互独立，可分别调试。

### 3.2 稳定跟踪判据（上板实测特征）

- 六路相关值形态：**IP 最高、IE/IL 居中、QP/QE/QL 贴近 0**，且含电文翻转；
- IQ 比值（能量集中度）接近 1（实测 0.96~1.00）；
- CNR 稳定（实测 42~51 dB-Hz）；
- 鉴频误差收敛到 ±20 Hz 内。

### 3.3 晶振精度（关键教训，与本项目第 3 轮结论互相印证）

- 作者原板晶振约 20 ppm，**无论怎么调参都无法稳定跟踪**；换用晶振 0.xx ppm、
  射频性能经硬件工程师测试的高性能板卡后一次成功。
- 即：**本地晶振精度是真实卫星跟踪能否稳定的硬件前提**。本项目 Pluto 内置 TCXO
  规格 ±25 ppm（L1 频偏最大约 ±39 kHz，超出捕获搜索 ±10 kHz），bias-T 到货做真实
  卫星前，务必先做频率校准 / 扩搜索窗 / 换 TCXO / 外部参考。

## 4. 真实卫星接收（第 15、16、17 篇）

### 4.1 真实卫星信号预期值（可作为本项目验收基准）

- GPS L1 真实卫星 CNR 实测 **38.8~48.7 dB-Hz**（开阔天台，多星 CNR 43~48 为典型）；
- IQ 比值 0.89~0.99；7 星同时跟踪定位成功。
- 定位结果与手机一致；与百度地图对比偏差约 200 m，原因是**百度使用火星坐标系
  （GCJ-02）而非 WGS-84**，不是接收机问题。

> ⚠ 对本项目直接相关：M4.2 硬件定位以「参考点上海」评估 133 m 误差，需确认参考点
> 与解算坐标同为 WGS-84；若参考点取自手机/地图 App，应先扣除坐标系差异再评估。

### 4.2 天线与环境

- 开阔天台/房顶效果最佳；作者家中窗台只能零星捕获 1~2 颗，信号弱无法验证——
  本项目 bias-T 到货后同样建议在开阔处测试（HANDOFF §9.1 已提）。
- 作者用 15 m 线缆把房顶天线引到书房调试，长线缆可行。

### 4.3 北斗 B1 扩展（对应本项目「多系统扩展」待办）

- B1：1561.098 MHz，带宽 4.092 MHz，码率 2.046 Mcps（GPS L1 的两倍）；
- 捕获：码相位间距减半即可（仍是半码片精度），其余流程与 L1 完全一致；
- 跟踪：环路参数与 L1 完全一致，通道数需扩展（作者设 21 通道仍被北斗占满）；
- 本项目已有 RINEX 3 读取能力，扩展北斗的算法侧改动量小，硬件侧需覆盖 B1 频点。

### 4.4 导航专用射频 MAX2771（可选硬件参考）

- 单芯片导航接收射频，带宽可达 36 MHz（GPS L1 + BDS B1 可一起收），
  比 AD9363 简单（自带单片机自动配置，SPI 可编程）；
- ADC 只用 **2-bit（幅度位+符号位）** 即可正常捕获跟踪——佐证本项目 12-bit ADC /
  int8 落盘有巨大余量；
- 中频 3.996 MHz、采样时钟直接用 TCXO（16.369 MHz）输出，带通滤波器中心=中频。

## 5. 失锁重捕与道路实测（第 19 篇）

- **简易失锁重捕**：CNR 低于阈值 → 释放该通道重新捕获。作者用它解决隧道/高架
  遮挡后的恢复，方法粗糙但有效——可对应本项目真实定位后的鲁棒性增强。
- **冷启动代价**：信号丢失后重新收星历要半分钟才能定位；保存星历（热启动）可大幅
  加速——真实定位后建议实现星历缓存。
- 性能曲线认知：从「跑通」到「可用」容易，从「良好」到「极致」难度指数上升；
  本项目先以「真实卫星定位成功」为目标即可。

## 6. 工程架构参考（第 5 篇）

- PL（FPGA）做相关积分与锁存，PS（软件）做环路运算、位同步、帧同步、PVT；
  捕获串行遍历 32 星，通道失锁 → 重捕或选星。
- 中断设计：505 µs 积分结果查询中断 + 10 ms 测量中断（观测量提取）；
  对应本项目若做实时流，需在 `step()` 数据块上对齐 1 ms/20 ms 处理边界。
- 流程：捕获 → 跟踪 → 位同步 → 帧同步 → 解电文 → 观测量提取 → PVT——
  与本项目全链路一一对应。

## 7. GPS 模拟器对照（第 3 篇）

- 作者用 gps-sdr-sim + RINEX 星历 + HackRF 发射，手机可定位，并记录星历中的
  可见星/坐标用于与自制接收机交叉验证——与本项目「TX 合成 + RX 闭环」思路一致；
- HackRF 自带晶振精度不足，需外接 TCXO——再次印证时钟是模拟/真实链路的公共痛点
  （本项目 TX/RX 同源抵消了误差，真实卫星时才会暴露）。

## 8. 对本项目的落地建议（按优先级）

1. **真实卫星前自查/校准**：确认混频方向；对晶振误差做一次校准（或用两段式宽范围
   捕获 `DopplerRange≥25000`）；参考点坐标系确认 WGS-84。
2. **跟踪加 FLL 辅助**：按「FLL 100 Hz → PLL 20 Hz」切换流程增强 `tracking.m`
   的高动态能力（对应 HANDOFF §9.2）。
3. **验收基准**：真实卫星 CNR 38~48 dB-Hz、IQ 比 ≥0.9、六路相关值形态、捕获结果
   与手机 GPS Test 交叉验证。
4. **鲁棒性**：CNR 阈值失锁重捕 + 星历缓存（热启动）。
5. **多系统**：北斗 B1 只需码相位间距减半，环路参数可复用；通道数按 ≥12（GPS）/
   21（GPS+北斗）规划。
